# 口播稿的拆页与视觉规则

## 目标

把口播稿转换成“视觉锚点”。Slide 帮观众抓住口播结构，不承担逐字字幕功能。

## 拆页

- 按论点、转折、对比、流程、案例和总结拆页，不按自然段机械拆分；
- 开场问题、核心结论、关键对比、流程、案例、总结通常各占一页；
- 相邻两页若表达同一观点，优先合并；
- 一页只保留一个可用一句话说清的中心；
- 不擅自补充业务数据、引用、实验结果或案例细节；
- 口播中只有语气重复、口头禅或转场词时，不单独成页。

## 每页内容上限

- 1 个核心标题；
- 1 个主要视觉结构；
- 1–3 个关键词、标签或短说明；
- 正文只有在定义、原句证据或步骤本身不可省略时保留；
- 中文标签尽量短，能用 4–12 个字说明就不写长句。

## 视觉结构选择

- **问题/结论**：大标题 + 单一核心符号；
- **两种概念**：左右对比或上下对比；
- **因果关系**：从左到右箭头；
- **固定步骤**：编号流程或时间线；
- **层级关系**：嵌套框或树状结构；
- **多个并列项**：统一规格卡片，避免颜色各不相同；
- **案例**：场景 → 动作 → 结果，未提供结果时不要编造；
- **总结**：回收前文结构，不新增概念。

连续两页避免使用完全相同的构图，但不要为了变化牺牲语义准确性。

## 默认风格

- 画幅：`1080 × 1440`（3:4），除非当前 frame 或用户指定其他尺寸；
- frame 横向排列，间距 `120px`，所有 frame 使用相同 `y`；
- 安全边距：四周至少 `80px`；
- 背景：白色；
- 主文字：`#1e1e1e`；
- 强调色：红色 `#e53935`；
- 辅助文字：`#6b7280`；
- 一页通常不超过 3 种有效颜色；
- 避免大片灰底、过多渐变、密集小字和无意义装饰；
- 优先 Excalidraw 手绘感和宽松留白。

## 录屏文字可读性（硬约束）

Slide 会被录制并可能在小屏设备上观看，文字必须在完整录制画幅下清晰可读，不能依赖观众放大画面。默认 `1080 × 1440` 画幅使用：

- 主标题 `72–96px`；
- 关键数字或唯一核心短语 `96–160px`；
- 正文、步骤和主要说明 `44–56px`；
- 标签、图例和箭头文字 `36–44px`；
- 来源或确实次要的辅助文字不小于 `32px`；
- 任何可见文字都不得小于 `32px`，也不能通过把长文缩成小字来塞进页面；内容放不下时，优先删减、缩短或拆页。

画幅不为 `1080 × 1440` 时，字号按 `min(frame.width / 1080, frame.height / 1440)` 等比例缩放，但最终仍要以完整录制画幅截图确认可读性。同类文字在所有 Slide 中保持字号层级一致。

用户提供参考图时，保持其布局意图和信息层级；不要复制受保护的品牌素材或直接扒取第三方资源。

## 图片与文字

- 标题、标签、说明、来源和箭头文字必须是 Excalidraw 原生 text；
- 图片里不要烘焙这些文字；
- 图片可以作为照片、截图、人物或视觉隐喻；
- 使用截图时保留可读主体，必要的圈选和说明使用原生矩形、箭头和文字；
- 没有合法素材时，优先用原生图形表达，不为“更好看”随意抓取图片。

## 口播稿到 Slide 的例子

口播：

```text
Skill、Workflow 和 Agent 真正的区别，不是用了什么模型，而是谁控制下一步。
```

不要整段贴入。生成：

```text
标题：谁控制下一步？
左侧：Workflow / 规则控制
右侧：Agent / 模型决策
中间：VS
```

## 统一验收

- 远看能先读到标题和主结构；
- 以完整录制画幅查看时，不放大也能清晰读出所有文字；
- 检查每个 text 元素的 `fontSize`：默认画幅没有小于 `32px` 的可见文字，正文、步骤和主要说明没有小于 `44px`；
- 箭头方向和连接对象符合语义；
- 同义术语统一，不把相近概念混成同一概念；
- 没有意外遮挡、越界或小于可读阈值的文字；
- Slide 顺序与口播的叙事顺序一致。
