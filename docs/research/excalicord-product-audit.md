# Excalicord 产品与录制实现审计

审计日期：2026-07-27
目标站点：[Excalicord](https://www.excalicord.com/)
公开前端资源：[当前生产 bundle](https://www.excalicord.com/assets/index-BbJnbZOE.js)

## 审计边界

本审计用于确定 Excalicap 的“核心创作功能 1:1”范围，以及需要替换的录制链路。结论来自两个不同口径：

1. 在桌面 Chrome 中对当前生产页面进行只读 UI 检查；
2. 对当前生产 bundle 中的用户文案、默认值、状态分支和录制逻辑进行静态核对。

没有启动真实录制，没有请求摄像头或麦克风权限，没有修改用户项目内容。

生产 bundle 是压缩后的公开交付物，只适合确认当前行为，不代表可以复制其私有源码或素材授权。

## 已验证事实：产品结构

### 编辑工作区

- 主体是嵌入式 Excalidraw 无限白板。
- 多页不是独立文档页，而是白板中的 Excalidraw `frame` 元素。
- Slide 按画布中的 `x` 坐标从左到右排序。
- 右侧悬浮幻灯片导航显示数字序号、删除按钮和添加按钮。
- 添加 Slide 时，新 Frame 默认出现在上一张右侧。
- Slide 的宽高比跟随当前录制比例。
- 点击右侧序号会缩放并滚动到对应 Frame。
- 录制准备态和录制态支持方向键切换 Slide。
- 录制准备态会高亮当前 Frame，并用遮罩弱化画框外区域。

### Slide 操作

- 添加 Slide。
- 删除 Slide。
- 点击数字导航到 Slide。
- 拖拽排序；排序本质上会交换 Frame 的横向位置并更新 Slide 名称。
- 选中 Frame 后使用 `Cmd/Ctrl+C` 复制整张 Slide。
- 随后使用 `Cmd/Ctrl+V` 在当前 Slide 后粘贴副本。
- 复制时同时处理 Frame 内元素、分组引用、绑定元素和容器引用。
- 录制过程中禁用会破坏 Slide 结构的编辑操作。

### Excalidraw 基础能力

当前页面直接暴露 Excalidraw 的主要桌面工具：

- 抓手和平移；
- 选择；
- 矩形、菱形、椭圆；
- 箭头和直线；
- 自由书写；
- 文字；
- 图片插入；
- 橡皮；
- 更多工具；
- 素材库；
- 缩放；
- 撤销和重做；
- 打开 `.excalidraw`；
- 保存 `.excalidraw`；
- 导出图片；
- 画布内查找；
- 清空画布；
- 画布背景颜色；
- Excalidraw 帮助入口。

Excalicap 应复用 `@excalidraw/excalidraw` 提供这些能力，不重新实现绘图引擎。

### 本地持久化

当前 Excalicord 的实现口径是：

- 场景元素和一部分 `appState` 保存到 `localStorage`；
- 二进制图片文件保存到 IndexedDB；
- 白板变更约一秒后自动保存；
- 录制过程中每十秒再次保存一次场景；
- 页面重新打开时恢复白板和图片；
- 录制设置保存在单独的 `localStorage` 项；
- 提词器速度和窗口尺寸也保存在本地。

这属于“单个本地工作区自动恢复”，不是多项目管理系统，也不是云同步。

## 已验证事实：录制设置

### 画幅预设

| ID | 名称 | 输出尺寸 |
| --- | --- | ---: |
| `16:9` | YouTube | `1920×1080` |
| `4:3` | 经典 | `1440×1080` |
| `3:4` | 小红书 | `1080×1440` |
| `9:16` | 抖音 | `1080×1920` |
| `1:1` | 正方形 | `1080×1080` |
| `custom` | 自定义 | 默认 `1920×1080` |

自定义范围：

- 宽度：`640–3840 px`；
- 高度：`480–2160 px`。

### 视觉设置

- 录制设置以居中的左右分栏 Modal 呈现。
- 左侧是实时构图预览。
- 右侧是滚动设置区。
- 背景分为全部、鲜艳、柔和、深色、自然。
- 支持随机选择壁纸。
- 包含渐变、纹理和图片背景。
- 支持内容区域圆角。
- 支持画布边距。
- 有边距时增加内容卡片阴影。

### 摄像头和麦克风

- 可选择是否显示摄像头。
- 摄像头尺寸可调。
- 摄像头支持圆形和圆角方形。
- 可切换摄像头设备。
- 可切换麦克风设备。
- 录制中不允许切换麦克风。
- 摄像头预览浮层可在工作区中拖动。
- 最终录制时，摄像头位置会映射到输出画幅。
- 摄像头画面横向镜像并按正方形中心裁切。

### 光标

- 可选择是否在成品中显示光标高亮。
- 可选择高亮颜色。
- 录制过程中可以临时隐藏或显示光标。

## 已验证事实：提词器

- 顶部录制控制区有独立提词器入口。
- 提词器是可拖动、可缩放的悬浮窗口。
- 支持输入或粘贴脚本。
- 支持自动滚动。
- 支持调节滚动速度。
- 支持调节窗口透明度。
- 文案明确说明提词器不会进入录制成品。
- 提词器窗口位置不持久化；速度和窗口尺寸会持久化。

生产 bundle 中存在“美颜模式”翻译文案，但当前 UI 和执行路径中没有确认到对应的可用控件。不能把仅存在于翻译表中的字符串当成已上线功能。

## 已验证事实：录制状态机

### 空闲态

- 设置；
- 提词器；
- 录制。

### 录制准备态

- 点击“录制”后不会立即编码；
- 当前录制 Frame 被高亮；
- Frame 外区域被遮罩；
- 可以取消；
- 可以确认开始录制；
- Slide 模式提示使用方向键切换。

### 录制态

- 显示计时器；
- 暂停；
- 继续；
- 停止；
- 动态显示或隐藏光标；
- 可以继续使用提词器；
- 免费产品逻辑会在 30 分钟时自动停止；
- 最后一分钟显示警告。

### 停止与异常

- 停止后显示“正在生成视频”；
- 成功后触发视频文件下载；
- 编码意外终止时尝试保留可用的部分文件；
- 无麦克风权限时允许无声录制并提示；
- WebM 转 MP4 失败时保留 WebM；
- 旧回退路径中的浏览器端转换限制为 `100 MB`。

Excalicap 不包含账号、付费和水印，因此不需要复刻免费版的 30 分钟商业限制；但需要设置技术性单段上限，并以稳定性测试为依据。

## 已验证事实：当前编码实现

当前 Excalicord 已经不是单一的 `MediaRecorder` 实现。生产 bundle 中存在三层路径：

1. 非 Safari 且支持 H.264 WebCodecs 时，优先使用 MediaBunny 风格的 WebCodecs + MP4 封装路径；
2. Safari 支持原生 MP4 `MediaRecorder` 时，使用原生 MP4；
3. 其他情况使用 VP9/VP8 WebM `MediaRecorder`，再尝试服务端或浏览器端转 MP4。

主要参数：

- 常规目标帧率：`30 fps`；
- Safari 原生 MP4 路径：`24 fps`；
- WebCodecs 视频目标码率：`8 Mbps`；
- AAC 音频目标码率：`192 kbps`；
- Safari 原生 MP4 视频目标码率：`10 Mbps`；
- `MediaRecorder` 以一秒为时间片接收数据。

WebCodecs 路径会尝试使用 OPFS 临时文件，说明原版已在规避长视频全部堆入内存的问题。

## 核心缺陷：录制渲染源仍然是屏幕 Canvas

尽管当前编码和 MP4 封装比早期推断更成熟，白板画面仍来自页面上的 Excalidraw Canvas：

1. 录制开始时查询 `.excalidraw` 下的多个 `canvas`；
2. 每帧读取这些已经按编辑窗口栅格化的 Canvas；
3. 根据编辑器容器和录制区域的矩形关系计算缩放；
4. 使用 `drawImage()` 将这些 Canvas 重绘到目标输出 Canvas；
5. 再叠加当前 DOM 文字输入状态、光标、摄像头、背景和水印；
6. 将目标 Canvas 交给编码器。

因此，编码器即使输出 `1620×2160`，白板细节也可能只是从较小的屏幕 Canvas 放大。编码链路升级不能修复源像素不足。

这与用户视频抽帧的现象交叉一致：

- Excalidraw 原生大字和线条相对清楚；
- 导入截图中的小字明显更软；
- 输出分辨率提高后，实际细节没有按比例增加。

## Excalicap 的 1:1 与差异化边界

### 应当 1:1 保留

- 原版整体页面布局；
- 无限白板；
- 横向 Frame 式 Slide；
- 右侧数字 Slide 导航；
- Slide 添加、删除、复制、粘贴、排序和方向键切换；
- 顶部 Excalidraw 工具栏；
- 左上主菜单；
- 左下缩放、撤销和重做；
- 右上设置、提词器和录制控制；
- 设置 Modal 的整体结构和选项；
- 录制准备态遮罩与当前 Frame 高亮；
- 摄像头浮层；
- 提词器；
- 暂停、继续、停止和计时器；
- 本地自动恢复；
- `.excalidraw` 打开、保存和图片导出；
- 中文和英文界面。

### 不进入产品范围

- Excalicord 品牌、Logo 和名称；
- “Made with Excalicord”水印；
- Google / 邮箱登录；
- Stripe 支付；
- Pro 授权；
- 分享解锁和营销增长；
- 移动端邮件发送链路；
- PostHog、Sentry 等原版业务遥测配置；
- 原版背景图片素材，除非逐项确认许可。

### 必须优于原版

- 白板内容不能从编辑器屏幕 Canvas 截取；
- 应从 Excalidraw 场景元素、原始二进制文件和目标 Frame 直接渲染；
- `1080×1440` 和 `1620×2160` 必须产生不同的真实细节；
- 需要保留原版 WebCodecs / MP4 / OPFS 级别的长录稳定性；
- 不为未来离线重导出额外长期保存摄像头、麦克风或完整时间线；
- 完成后清理临时编码文件。

## 设计推断

1. 直接改用简单 Blob 数组式 `MediaRecorder` 会在长录稳定性上倒退，不应作为最终架构。
2. 最小正确改动不是重写整个录制器，而是替换“白板画面如何进入输出 Canvas”这一段：
   - 原版：屏幕 Canvas → 缩放 → 输出 Canvas；
   - Excalicap：场景数据 + 原始图片 → 目标尺寸渲染缓存 → 输出 Canvas。
3. MediaBunny/WebCodecs、Safari 原生 MP4 和 WebM 回退可以作为编码策略参考，但必须基于官方 API 和实际依赖能力重新实现，不能复制生产 bundle。
4. 因为原版多页本质是 Frame，高清渲染器可以只渲染当前 Frame 内的元素；Slide 切换时更新缓存，而不是重绘整个无限画布。
5. 第一阶段必须先做高清渲染与编码纵向验证；通过后再扩充完整的 1:1 UI。
