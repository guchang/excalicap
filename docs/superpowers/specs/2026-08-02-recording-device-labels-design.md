# 录制准备面板显示实际媒体设备名称

## 目标

在录制准备面板中显示本次 `getUserMedia()` 实际取得的摄像头和麦克风名称，让多设备用户在开始录制前确认输入来源。

## 产品边界

- 设备名称以成功取得的 `MediaStreamTrack.label` 为真值，不以“系统默认”配置或 `enumerateDevices()` 列表推测实际设备。
- 录制准备面板只显示实际设备，不在面板内热切换媒体轨道。
- “更换设备”会取消本次准备、释放已取得的媒体轨道并打开现有录制设置。
- 不修改编码格式、双录制协调器、结果文件、浏览器权限或录制中的设备切换行为。
- 不新增依赖。

## 界面

录制准备面板沿用现有输出与格式卡片。设备区域显示：

```text
摄像头
FaceTime HD Camera

麦克风
MacBook Pro 麦克风
                               [更换设备]
```

显示规则：

- 设备已启用且轨道获取成功、`label` 非空：显示实际轨道名称。
- 设备已启用且轨道获取成功、`label` 为空：显示“已连接，但浏览器未提供设备名称”。
- 设备未启用：摄像头显示“未启用”；麦克风显示“未启用，将进行无声录制”。
- 设备已启用但获取失败：显示“连接失败”；现有警告继续解释降级行为。
- 过长名称单行省略，并通过 `title` 暴露完整名称。

## 数据流

1. `acquireEnabledMedia()` 继续分别获取摄像头流和麦克风流。
2. `App` 从成功获取的第一条视频轨和第一条音频轨读取 `label`。
3. `App` 根据产品设置与实际流形成摄像头、麦克风的显示状态。
4. `RecordingPreparation` 只负责呈现名称和状态。
5. 点击“更换设备”时复用取消准备的清理逻辑，然后打开 `SettingsDialog`。

`enumerateDevices()` 仍只服务于设置页的设备列表，不作为录制准备面板的实际设备真值。

## 错误与降级

- 浏览器拒绝或无法获取某个设备时，保持现有“只录白板和声音”或“无声录制”降级。
- 空 `label` 不视为获取失败，也不使用目录中可能不对应实际轨道的名称补齐。
- “更换设备”必须停止准备阶段已借用的摄像头和麦克风轨，避免设备指示灯和占用残留。

## 验证

- 组件测试覆盖实际设备名、空名称、未启用、获取失败和长名称提示。
- App 测试覆盖从实际轨道向面板传递名称。
- App 测试覆盖“更换设备”释放媒体轨并打开现有设置。
- 运行相关测试、全量测试、类型检查、生产构建和 `git diff --check`。
