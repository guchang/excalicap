# Excalicap 产品与高清录制设计规格

> 日期：2026-07-27
> 状态：方案已确认，待实施计划
> 产品定位：保持 Excalicord 核心创作体验与界面结构，重做高清录制链路
> 相关调研：
> - [`docs/research/excalicord-product-audit.md`](../../research/excalicord-product-audit.md)
> - [`docs/research/recording-feasibility.md`](../../research/recording-feasibility.md)

## 1. 目标

Excalicap 是一个本地优先的白板视频录制工具。用户在 Excalidraw 白板中用 Frame 组织多张幻灯片，录制时叠加摄像头、麦克风、光标和背景，最终得到适合发布的清晰视频。

本项目的两条产品原则是：

1. **核心产品体验与原版一致。** 保留 Excalicord 当前编辑器布局、主要交互、录制设置和状态反馈，让熟悉原版的用户无需重新学习。
2. **录制清晰度必须优于原版。** 白板层直接从 Excalidraw 场景数据按目标像素渲染，不再放大编辑器屏幕 Canvas。

第一版只解决已经确认的创作与录制需求，不扩展为云端视频编辑器。

## 2. 范围

### 2.1 第一版包含

- Excalidraw 白板编辑；
- 以 Excalidraw Frame 表示 Slide；
- Slide 新建、删除、切换、排序、复制和粘贴；
- 画幅比例和自定义输出尺寸；
- 背景、圆角、画布留白；
- 摄像头开关、设备、大小和形状；
- 麦克风开关和设备；
- 光标显示和颜色；
- 可拖动、可缩放的提词器；
- 录制准备、开始、暂停、继续、停止和异常处理；
- `1080×1440 px` 与 `1620×2160 px` 等固定目标分辨率录制；
- 本地项目保存、自动保存、`.excalidraw` 打开/保存和图片导出；
- 录制分片临时落 OPFS，最终视频由用户保存；
- 运行时能力检测与录制诊断信息。

### 2.2 第一版不包含

- 账号、登录、订阅、支付、许可证校验；
- 云端同步、团队协作、在线素材市场；
- 原版营销页面、商业入口和水印；
- 视频时间线、逐轨剪辑、字幕轨；
- 单独永久保存的摄像头原始轨；
- 单独永久保存的麦克风原始轨；
- 完整操作时间线或逐帧中间文件；
- 为未来“路线三”预存额外录制资产；
- 未验证许可的原版背景照片、纹理或其他受保护素材。

### 2.3 路线二与存储边界

第一版采用“路线二”：用独立目标分辨率 Canvas 完成白板、背景、摄像头和光标的实时合成，再直接录制合成结果。

如果路线二通过验收，它已经满足当前需求。项目不会同时为路线三保留原始音视频轨、操作时间线或中间帧，因为这些数据会增加空间占用、清理复杂度和隐私风险，却不改善当前成品视频。

以下内容仍然需要保存，但不属于路线三的冗余数据：

- Excalidraw 工程元素、`appState` 和 `BinaryFiles`；
- 用户插入工程的原始图片；
- 少量界面和录制设置；
- 录制期间尚未封装完成的 OPFS 临时分片；
- 用户最终确认保存的成品视频。

## 3. 原版一致性与合法素材边界

### 3.1 保持一致的界面骨架

桌面端默认界面沿用原版的空间关系：

- 中央是 Excalidraw 无限白板，横向摆放多个 Slide Frame；
- 顶部中央是 Excalidraw 工具栏；
- 顶部右侧依次提供设置、提词器、录制和素材入口；
- 左上角保留主菜单；
- 左下角保留缩放、撤销和重做；
- 右侧提供悬浮的编号 Slide 导航；
- 弹窗、浮层、录制准备态和录制态遵循原版的信息层级和操作顺序。

“与原版一样”指核心布局、信息架构、控件位置、交互反馈和状态切换保持一致，不表示复制原版私有源码、商标或未授权素材。

### 3.2 品牌与背景素材

- 产品名称、图标和品牌文字使用 Excalicap；
- 纯色和渐变背景可按相同选择器结构重新实现；
- 原版背景选择器的分类、布局和交互保持一致；
- 图片与纹理背景只使用自制素材、明确可商用素材或逐项核验过许可证的素材；
- 在没有明确授权证据时，不下载、不复制、不打包原版照片和纹理；
- 合法替代素材应尽量匹配原版的色调、明暗关系和使用场景，但不要求像素级复制素材内容。

## 4. 功能规格

### 4.1 Excalidraw 编辑器

复用 `@excalidraw/excalidraw`，不重新实现绘图引擎。第一版应提供：

- 手型工具；
- 选择；
- 矩形、菱形、椭圆；
- 箭头、线段；
- 自由绘制；
- 文字；
- 图片；
- 橡皮擦；
- 更多工具；
- 素材库；
- 缩放、撤销、重做；
- 查找；
- 画布背景颜色；
- 重置画布；
- 打开和保存 `.excalidraw`；
- 导出 PNG、SVG 等 Excalidraw 已支持的图片格式；
- 中文与英文界面。

首个受支持版本固定为 `@excalidraw/excalidraw@0.18.1`。升级必须单独验证导出、Frame、字体和图片行为，不能依赖未固定的 `master` 私有接口。

### 4.2 Slide

每张 Slide 是一个 Excalidraw Frame，Frame 同时承担：

- 内容归属；
- 画幅逻辑边界；
- 导出裁切边界；
- 录制时的当前页面状态。

必须支持：

- 新建 Slide；
- 删除当前 Slide；
- 点击右侧编号导航切换；
- 使用方向键切换；
- 拖动排序；
- 复制和粘贴 Slide；
- 复制时保留属于该 Frame 的元素关系；
- 粘贴时重新建立新的 Frame 引用，避免指向原 Slide；
- 录制准备时高亮当前 Frame、弱化其他 Frame；
- 录制中锁定会破坏 Frame 结构的编辑操作。

### 4.3 输出比例和尺寸

预设沿用原版：

| 比例 | 场景 | 输出尺寸 |
| --- | --- | --- |
| `16:9` | 横屏 | `1920×1080 px` |
| `4:3` | 经典 | `1440×1080 px` |
| `3:4` | 小红书 | `1080×1440 px` |
| `9:16` | 竖屏 | `1080×1920 px` |
| `1:1` | 方形 | `1080×1080 px` |
| 自定义 | 用户输入 | 默认 `1920×1080 px` |

自定义尺寸边界：

- 宽度：`640–3840 px`；
- 高度：`480–2160 px`；
- 输入不合法时在开始录制前明确提示，不自动静默修正。

高清验证档额外包含 `1620×2160 px / 30 fps`，用于证明增加的是实际场景细节，而不是把低分辨率画面放大。

### 4.4 视觉设置

设置弹窗保留原版结构：

- 画幅预设与自定义尺寸；
- 背景分类：全部、鲜艳、柔和、深色、自然；
- 随机背景；
- Slide 圆角；
- 画布留白；
- 摄像头；
- 麦克风；
- 光标。

背景绘制发生在最终合成 Canvas 中。Slide 内容层只负责透明或带自身页面底色的白板内容，避免把背景素材烘焙进工程数据。

### 4.5 摄像头

支持：

- 显示/隐藏；
- 摄像头设备选择；
- 大小；
- 圆形、圆角矩形等原版已有形状；
- 在预览中拖动位置；
- 录制前权限和实时画面检查。

摄像头视频帧绘制到最终合成 Canvas，录制引擎只接收合成 Canvas 的单一视频轨，不直接加入摄像头视频轨。

### 4.6 麦克风

支持：

- 启用/禁用；
- 麦克风设备选择；
- 录制前权限检查；
- 输入电平提示；
- 将单一麦克风音频轨加入最终录制流。

第一版不承诺录制过程中无缝热切换麦克风。麦克风断开时停止录制、尽力保存已经完成的内容，并给出明确原因。

### 4.7 光标

支持：

- 显示/隐藏；
- 原版已有的光标颜色；
- 只在最终合成 Canvas 绘制；
- 按输出尺寸与编辑器坐标映射位置；
- 离开当前 Slide 时隐藏，避免录入无关区域。

### 4.8 提词器

提词器应：

- 可打开和关闭；
- 可拖动；
- 可缩放；
- 支持编辑文字；
- 支持自动滚动；
- 支持滚动速度；
- 支持透明度；
- 保持在操作者界面上；
- 永远不进入最终录制 Canvas。

## 5. 系统架构

### 5.1 模块

第一版按职责分为：

1. **Project Storage**：保存场景、文件、Slide 顺序和应用设置；
2. **Editor**：承载 Excalidraw 和编辑器 UI；
3. **Slide Service**：管理 Frame、顺序、导航和复制关系；
4. **High-resolution Slide Renderer**：从场景数据生成目标像素白板层；
5. **Camera Controller**：管理权限、设备和视频帧；
6. **Compositor**：合成背景、白板、摄像头和光标；
7. **Recording Engine**：能力探测、编码、暂停、停止和临时落盘；
8. **Diagnostics**：记录尺寸、帧率、延迟、编码格式、分片和错误。

### 5.2 数据流

```text
elements + appState + BinaryFiles + current Frame
                     │
                     ▼
 exportToCanvas(exportingFrame, getDimensions)
                     │
                     ▼
       目标尺寸的白板内容缓存
                     │
                     ▼
背景 + 白板缓存 + 摄像头 + 光标
                     │
                     ▼
       最终 HTMLCanvasElement
                     │
                     ▼
             RecordingEngine
                     │
                     ▼
        OPFS 临时分片/临时文件
                     │
                     ▼
           可播放的最终视频
                     │
                     ▼
             用户选择保存位置
                     │
                     ▼
          验证保存成功后清理临时数据
```

### 5.3 不可退让的渲染边界

白板层的真值必须是：

- `elements`；
- `appState`；
- 完整 `BinaryFiles`；
- 当前 `exportingFrame`；
- 明确的目标像素和 `scale`。

禁止把 `.excalidraw` 下的编辑器显示 Canvas 作为录制白板源，也禁止对它做 `drawImage(editorCanvas, ...)` 后放大。这是原版录制模糊的核心根因。

## 6. 高清白板渲染

### 6.1 固定尺寸导出

对当前 Frame 调用 `exportToCanvas()`：

- 传入当前场景元素；
- 传入录制所需的 `appState`；
- 传入完整 `files`；
- 传入 `exportingFrame`；
- 在 `getDimensions()` 中同时返回目标 `width`、`height` 和匹配的 `scale`。

不能用 `maxWidthOrHeight` 替代固定尺寸，因为它只限制最大边，不保证得到严格目标宽高。

示例：逻辑尺寸为 `1080×1440` 的 Frame 输出 `1620×2160 px` 时，渲染比例为 `1.5`。

### 6.2 白板缓存与动态合成

为了避免每个视频帧都完整执行静态导出：

- 只在场景内容、当前 Slide 或输出设置变化时更新高清白板缓存；
- 背景、摄像头和光标由 Compositor 按视频帧刷新；
- 连续书写时允许合并过密的场景变更，但必须保证视觉更新延迟达标；
- 不预设复杂的局部渲染器，先测量 `exportToCanvas()` 的真实延迟；
- 只有测量证明完整导出不达标，才评估局部动态笔迹层或稳定的官方渲染入口。

首要性能指标：

- 普通场景 `scene_update_latency_ms` 的 `p95 < 100 ms`；
- 复杂场景 `scene_update_latency_ms` 的 `p95 < 200 ms`。

### 6.3 图片导入清晰度

Excalidraw 当前默认 `imageOptions.maxWidthOrHeight = 1440 px`。如果沿用默认值，高分辨率截图可能在进入工程时已经被缩小，后续高清导出无法恢复细节。

因此第一阶段必须：

- 显式覆盖 `imageOptions.maxWidthOrHeight`；
- 根据支持的输出尺寸设定足够的图片最大边；
- 同步评估并调整 `maxFileSizeBytes`；
- 录制前检查每个图片元素的 `fileId` 是否存在；
- 实际解码图片或执行测试导出；
- 检查原图像素是否足以覆盖视频中的目标显示尺寸；
- 对分辨率不足的素材明确提示，不宣称已经得到高清内容。

图片导入上限是 P0 约束，不得等到录制阶段再补救。

### 6.4 字体

- 固定并自托管 Excalidraw 所需字体；
- 在 Excalidraw 初始化前设置正确的资源路径；
- 录制前等待目标字体和字形加载；
- 使用中文、英文、数字和小字号组合做像素对照；
- 字体缺失或回退时阻止开始录制并明确提示。

不能仅以 `exportToCanvas()` Promise 成功作为字体正确的证据，因为单个字体加载失败可能只记录错误而不让整个导出失败。

## 7. 录制引擎

### 7.1 统一接口

录制实现通过小型适配接口隔离：

```ts
interface RecordingEngine {
  probe(options: RecordingOptions): Promise<RecordingCapability>;
  start(options: RecordingOptions): Promise<void>;
  pause(): Promise<void>;
  resume(): Promise<void>;
  stop(): Promise<RecordingResult>;
  abort(reason: RecordingAbortReason): Promise<PartialRecordingResult | null>;
}
```

接口用于隔离浏览器录制路径，不提前抽象时间线、轨道编辑或云端发布能力。

### 7.2 第一选择：MediaRecorder

第一轮验证先使用 `MediaRecorder`：

1. `MediaRecorder.isTypeSupported()` 初筛候选容器和编码组合；
2. `MediaCapabilities` 在可用时补充查询；
3. 用目标设备、目标分辨率和真实音频执行 `5–10 s` 预录；
4. 核对实际 `MediaRecorder.mimeType`；
5. 播放预录文件并检查轨道、时长和尺寸；
6. 通过后才允许正式录制。

优先选择可直接得到目标发布格式的组合；若运行时只支持 WebM，应明确展示实际格式，不能仅通过扩展名伪装为 MP4。

### 7.3 升级条件：WebCodecs + Mediabunny

只有真实验收证明下列至少一项不达标时，才进入第二层编码实现：

- 目标浏览器不能生成可接受的 MP4/H.264/AAC；
- `1620×2160 px / 30 fps` 持续掉帧；
- 暂停后时间轴不符合产品语义；
- 长录分片或最终文件无法可靠落盘；
- 抽帧画质在合理码率下仍明显不达标；
- WebCodecs 预研能够以证据证明改善上述问题。

如果 `MediaRecorder` 已通过验收，不因“未来可能需要”引入 Mediabunny。

### 7.4 分片和 OPFS

- `dataavailable` 到达后立即进入串行写入队列；
- OPFS 只作为录制中的临时工作区；
- 开始前使用存储估算提示配额风险；
- 监控异常大的分片和写入延迟；
- 停止时等待最后一个分片和全部写入完成；
- 最终文件封装并验证可播放后，再交给用户保存；
- 确认用户保存成功后清理 OPFS 临时数据；
- 保存失败时保留可恢复的临时结果并明确提示。

OPFS 不作为永久成品库，也不承诺在用户清理站点数据后仍可恢复。

## 8. 状态和异常

### 8.1 录制状态

状态机至少包含：

- `idle`：普通编辑；
- `preparing`：检查尺寸、字体、图片、摄像头、麦克风、存储和编码；
- `ready`：当前 Frame 高亮，等待用户开始；
- `recording`：持续合成和编码；
- `paused`：停止计入有效录制时长；
- `stopping`：等待最后分片、封装和验证；
- `saving`：用户保存最终文件；
- `completed`：保存完成并可清理临时数据；
- `failed`：展示原因和可恢复结果。

状态切换必须防止重复开始、重复停止和未完成封装时关闭。

### 8.2 设备中断

- 摄像头断开：使用清晰的占位画面替代摄像头区域，白板录制继续，并立即提示；
- 麦克风断开：第一版停止录制，保存已完成内容并提示原因；
- 不承诺在同一次录制中热切换音频轨；
- 权限在准备阶段被拒绝时，不进入录制态。

### 8.3 页面隐藏和系统休眠

浏览器后台可能限制 `requestAnimationFrame()`，系统休眠也会破坏实时帧和时间轴。

第一版采用 fail-closed：

- 页面被隐藏时自动暂停；若当前浏览器无法保证有效暂停，则停止并保存；
- 恢复前重新检查设备和录制引擎状态；
- 检测到明显时间跳变时停止录制并解释原因；
- 不在后台静默生成可能缺帧或音画不同步的视频。

### 8.4 资源缺失

- 缺少图片文件：阻止录制；
- 图片无法解码：阻止录制；
- 字体缺失或回退：阻止录制；
- OPFS 写入失败：停止并尽力返回已完成内容；
- 配额明显不足：开始前警告或阻止；
- 编码器运行时失败：停止、保存可恢复结果并输出诊断。

## 9. 本地持久化

### 9.1 存储分工

`localStorage` 只保存少量设置：

- 最近画幅；
- 背景选择；
- 摄像头布局；
- 光标设置；
- 提词器偏好；
- 其他体积小、可丢失的 UI 偏好。

IndexedDB 保存：

- Excalidraw `elements`；
- 必要的 `appState`；
- `BinaryFiles`；
- Slide 顺序和当前 Slide；
- 项目元数据；
- 自动保存状态。

OPFS 保存：

- 当前录制的临时分片或临时封装文件；
- 必要的故障恢复信息；
- 不保存原始摄像头轨、原始麦克风轨、操作时间线和中间帧序列。

### 9.2 保存时机

- 场景变更后做防抖自动保存；
- 录制中定期确认项目状态已持久化；
- 开始录制前执行一次强制保存；
- 停止录制后保存最终项目状态；
- 自动保存失败不能静默，必须提示用户。

## 11. 验收标准

### 11.1 高清渲染

| 指标 | 通过条件 |
| --- | --- |
| 输出尺寸 | 文件严格为目标 `width × height px` |
| 渲染来源 | 白板层只来自 Excalidraw 场景导出，不读取编辑器显示 Canvas |
| 真实细节 | `1620×2160 px` 抽帧相比 `1080×1440 px` 能显示额外真实细节 |
| 图片导入 | 高清测试图进入 `BinaryFiles` 后未被静默限制到默认 `1440 px` |
| 字体 | 中英文、数字和小字号均使用预期字体，无静默回退 |
| 普通场景延迟 | `scene_update_latency_ms p95 < 100 ms` |
| 复杂场景延迟 | `scene_update_latency_ms p95 < 200 ms` |

### 11.2 视频和音频

| 指标 | 通过条件 |
| --- | --- |
| 目标帧率 | `30 fps` |
| 掉帧率 / `dropped_frame_rate` | 正常测试样本 `< 1%` |
| 音画时差 / `av_sync_delta_ms` | 30 分钟录制结束时绝对值 `< 100 ms` |
| 暂停语义 | 暂停 `120 s` 不进入最终有效视频时长 |
| 可播放性 | 最终文件可在目标本地播放器和实际发布流程播放 |
| 格式真实性 | 文件容器、扩展名和 `mimeType` 一致 |

### 11.3 长录和存储

| 指标 | 通过条件 |
| --- | --- |
| 内存 | 长录期间没有随视频时长线性增长的无界 Blob 数组 |
| 临时存储 | 分片持续落 OPFS，并能显示 `temporary_storage_mb` |
| 最终保存 | 只在文件可播放且用户保存成功后清理临时数据 |
| 故障处理 | 保存失败、配额不足和写入失败均有明确提示和可恢复结果 |
| 冗余数据 | 不生成路线三的原始音视频轨、时间线或逐帧中间文件 |

### 11.4 原版体验

- 主界面空间关系与原版一致；
- 核心工具、Slide 操作和录制设置可从原版对应位置找到；
- 提词器不进入录制；
- 录制准备态能明确当前 Slide；
- 商业、账号和营销功能没有混入核心工作区；
- 背景选择器保持原版布局和交互，但素材来源全部可证明合法。

## 12. 验证证据

Phase 1 和发布前验证不能只靠肉眼预览。至少保留：

- 运行时能力探测结果；
- 实际 `mimeType`、编码器、分辨率和目标码率；
- `scene_update_latency_ms` 分布；
- 目标帧、已合成帧和掉帧计数；
- OPFS 分片数量、异常分片大小和临时占用；
- 录制文件的媒体探测结果；
- 关键时间点抽帧；
- `1080×1440 px` 与 `1620×2160 px` 的局部放大对照；
- 30 分钟音画同步检查；
- 120 秒暂停时长检查；
- 字体、图片缺失、设备断开和配额不足的异常测试结果。

媒体文件使用 `ffprobe` 或同等工具核验轨道、容器、编码、尺寸、帧率和时长；画质用同一场景的抽帧做像素级或局部放大比较。

## 14. 设计决策摘要

1. 保持原版核心界面和交互，品牌改为 Excalicap。
2. 原版背景选择器结构照旧，照片和纹理使用有许可证的合法替代素材。
3. 多页继续用 Excalidraw Frame，不引入独立幻灯片文档模型。
4. 白板录制源必须是目标尺寸的场景直出 Canvas，禁止放大屏幕 Canvas。
5. 白板层按场景变化更新缓存，摄像头和光标按视频帧动态合成。
6. 图片导入阶段显式突破默认 `1440 px` 上限，这是高清链路的 P0 条件。
7. 第一轮先用 MediaRecorder 做真实验证；只有验收失败才升级 WebCodecs + Mediabunny。
8. OPFS 只存录制临时数据，最终保存成功后清理。
9. 路线二通过即满足需求，不为路线三额外保存原始轨、时间线或中间帧。
10. 先完成最小高清录制验证器，通过后再建设完整原版 UI。
