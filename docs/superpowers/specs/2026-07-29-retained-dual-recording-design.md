# Excalicap 最近录制保留与双视频输出设计

## 目标

修复录制结果面板关闭后无法再次下载的问题，并在启用摄像头时同时生成：

1. 合成成片：白板、摄像头效果、激光笔、光标与麦克风声音。
2. 摄像头原片：摄像头原始矩形画面与麦克风声音。

## 已确认产品决策

- 采用两个 `MediaRecorder` 同步录制，不在录制结束后进行二次转码。
- 摄像头原片带麦克风声音。
- 摄像头原片保留摄像头真实矩形画面，不裁圆、不加圆角、白边、阴影或位置效果。
- 摄像头原片不烘焙“镜像画面”设置；镜像仅作用于合成成片。二次剪辑需要镜像时由剪辑软件水平翻转。
- 不尝试输出带透明通道的圆形视频。
- 最近一次成功录制只保留在当前页面会话，不永久写入 IndexedDB。
- 不注册新的键盘快捷键。

## 为什么不输出透明圆形视频

常规 MP4/H.264 没有适合该场景的透明通道。WebM/VP9 Alpha 在浏览器 `MediaRecorder`、硬件编码和剪辑软件中的兼容性不稳定，不能作为可靠产品能力。

摄像头原片以矩形视频输出后，用户可以在剪映、Final Cut Pro、Premiere 或 DaVinci Resolve 中使用圆形蒙版、智能抠像或绿幕重新合成。

## 录制架构

录制准备阶段继续只申请一套摄像头和麦克风设备流。开始录制时创建两个相互独立的录制任务：

### 合成录制任务

- 视频来源：合成 Canvas 的视频轨。
- 音频来源：麦克风音轨。
- 编码能力：沿用现有 `selectRecorderCapability` 结果。
- 临时存储：独立 `ChunkSink`。

### 摄像头录制任务

- 仅在已启用并成功取得摄像头视频轨时创建。
- 视频来源：摄像头原始视频轨。
- 音频来源：麦克风音轨。
- 编码能力：与合成录制任务使用同一种 MIME 类型和编码参数，便于剪辑兼容。
- 临时存储：另一个独立 `ChunkSink`，不能与合成录制任务共享。

两个录制任务接收同一次开始、暂停、继续和停止操作。停止时并行等待两个任务完成；只有两项结果都处理完后才停止设备流。

为了避免一个录制任务结束时停止另一个任务仍在使用的共享设备轨，录制任务不拥有摄像头和麦克风源轨的生命周期。设备源轨继续由 App 的 `stopDevices()` 统一停止；Canvas 捕获轨在录制收尾时单独停止。

如果摄像头录制任务失败但合成成片成功：

- 保留并展示可用的合成成片。
- 结果面板显示“摄像头原片生成失败”及具体错误。
- 不因摄像头原片失败而丢弃合成成片。

如果合成成片失败：

- 本次录制视为失败。
- 丢弃本次失败录制产生的摄像头原片片段。
- 保留上一轮成功录制结果及其下载入口。
- 只显示本次错误，不用失败结果替换上一轮成功结果。

## 最近录制的生命周期

当前实现把结果面板是否显示和视频是否保留绑定在同一个 `download` 状态中。新设计拆分为：

- `recordingResult`：最近一次成功生成的录制资产。
- `recordingResultOpen`：结果面板是否显示。
- `recordingError`：本次操作错误。

`recordingResult` 包含：

- 合成视频资产，必选。
- 摄像头原片资产，可选。
- 摄像头原片错误，可选。
- 录制完成时间。

每项视频资产包含：

- Blob URL。
- 下载文件名。
- MIME 类型。
- 文件大小。

### 保留规则

- 关闭结果面板只把 `recordingResultOpen` 设为 `false`。
- 关闭面板不清空 `recordingResult`，不调用 `URL.revokeObjectURL()`。
- 存在结果时，右侧控制栏显示“上次录制”按钮。
- 点击“上次录制”重新打开结果面板。
- 开始新录制时不删除上一轮结果。
- 新录制失败时，上一轮结果仍然可重新打开和下载。
- 新录制成功后才撤销上一轮所有 Blob URL，并用新结果替换。
- App 卸载或页面刷新时撤销当前所有 Blob URL。
- 不跨页面刷新保存视频，避免大文件长期占用浏览器磁盘空间。

## 文件命名

同一次录制使用同一个时间戳：

- 合成成片：`Excalicap-YYYYMMDD-HHmmss.mp4` 或 `.webm`。
- 摄像头原片：`Excalicap-camera-YYYYMMDD-HHmmss.mp4` 或 `.webm`。

> 摄像头原片生成失败：具体错误。合成成片仍可下载。

## 右侧控制栏

存在最近录制结果时，在提词器与录制按钮之间增加一个条件显示的“上次录制”图标按钮：

```text
┌────────┐
│  设置   │
├────────┤
│ 提词器  │
├────────┤
│上次录制 │
├────────┤
│  录制   │
└────────┘
```

不存在录制结果时不显示该按钮，保持当前控制栏不变。

- `合成成片`
- `白板 + 摄像头 + 激光笔 + 声音`
- `下载合成视频`
- `摄像头原片`
- `原始矩形画面 + 麦克风声音`
- `下载摄像头原片`
- `本次未启用摄像头，因此没有摄像头原片。`

- `上次录制`
- `返回白板`

## 测试要求

### 录制协调器

- 有摄像头时创建两个独立录制任务和两个独立 `ChunkSink`。
- 没有摄像头时只创建合成录制任务。
- 开始、暂停、继续、停止同时作用于全部活动任务。
- 两个输出都带麦克风音轨。
- 摄像头任务失败不会清除已经成功的合成成片。
- 合成任务失败不会替换或清除上一轮成功结果。
- 共享摄像头和麦克风源轨只由 App 统一停止。

### 结果生命周期

- 关闭面板后最近录制资产仍然存在。
- “上次录制”可以重新打开同一结果。
- 新录制开始时不撤销旧 Blob URL。
- 新录制失败时旧结果仍然存在。
- 新录制成功时撤销旧结果 URL 并替换结果。
- 页面卸载时撤销全部当前结果 URL。

### 结果面板

- 有摄像头时显示两个独立下载入口。
- 没有摄像头时只显示合成成片和明确说明。
- 摄像头原片失败时仍可下载合成成片。
- 两个下载文件名使用同一时间戳并有明确区分。

## 非目标

- 不输出透明通道视频。
- 不烘焙摄像头原片的圆形、圆角、白边、阴影、位置或镜像。
- 不把录制视频永久保存到 IndexedDB。
- 不实现录制历史列表，只保留最近一次成功结果。
- 不改变白板编辑、Slide、提词器、项目文件保存或素材库。
